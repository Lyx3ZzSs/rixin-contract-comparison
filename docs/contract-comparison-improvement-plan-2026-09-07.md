# 合同比对五类问题优化方案

日期：2026-09-07。状态：待实施的工程方案。本次只核查当前工作区代码与历史审计记录，未修改业务代码、运行回放或验证生产配置。工作区已有大量修改，本方案以这些文件的当前内容为依据，不代表已部署版本。

**建议保留当前 OCR、版面解析和程序化 diff 主链路，先补齐源内容保留与字段状态，再统一跨页逻辑结构，最后优化候选消歧和印章主体关联。** 五类问题应分别修复产生错误的阶段，同时共用证据与决策模型。减少误报必须与保留真实变化一起验收。

## 2. 共用的数据和决策约定

处理顺序：原始提取结果 → 带来源的逻辑内容 → 候选关系 → 关系选择 → 字段／文本差异 → 证据校验 → 结果展示。

- **原始证据可追溯。** 原 PDF、OCR 原文、字符／行坐标作为源记录；规范化、拼接、修复创建派生对象。每次转换记录输入、输出、规则版本和源引用。优先扩展现有模型，不引入全量重构前置条件。
- **逻辑身份与位置分离。** 逻辑条款或表格允许包含多页片段；源引用至少包含文档侧、页码、block、文字范围和可用坐标。缺少精确坐标时明确定位精度，不能借用其他页的框。
- **对应关系与内容变化分离。** 两条金额不同的付款条款可以确定为对应条款，随后报告金额变化。语义相似不能抹平数字、否定词、义务主体和条件差异。
- **确定一致、确定变化、待核验分开。** 当前 `change_decision=CONFIRMED` 可能用于确认空白一致；增加或明确复用独立的 `change_kind`（如 unchanged/modified/added/removed），展示和计数必须同时读取它。不要仅凭 CONFIRMED 生成变化条目。
- **不同事实分别确定。** 印章存在、章文内容、签署区域归属分别记录结论及证据。归属未知不妨碍确认存在；存在确定不自动提高归属置信度。
- **不确定候选有去向。** 修复拒绝、配对歧义、识读失败进入待核验或诊断记录；确认一致的对象无需作为差异展示。不能把候选全隐藏来降低误报率。

## 3. 表格金额：修复前后逐项核对

目标：原始提取已有的金额不会在结构修复中无解释消失；真实金额变化能进入 diff。

1. 在每次摘要拆分、续行合并、重复清理、行消费前提取金额出现项，记录原文、规范化值、单位、行列语义和源位置。同值重复出现仍保留不同身份；单位不明确时保留未知，不擅自折算。
2. 为每个输入出现项记录输出去向：保留、迁移、规范化或有证据的 OCR 重复消除。源坐标和字符范围用于判断同一出现项，不能只按金额相等去重。
3. 修复只有通过来源覆盖校验才能接受。金额无去向、凭空新增、串列或移动到无关项目时，撤销该次修复，保留输入结构与失败原因。未通过校验的结果不能继续用于确定删除或确定一致。
4. 回退结构仍不足以比较时，使用同侧原始 OCR 和局部图像复核。禁止用另一份合同的内容反填本侧。乘积、合计关系只作异常提示，不能据此改写原金额。
5. 同时保留最终整表检查，捕获多步修复组合造成的丢失。输入阶段已经漏识别的金额另归提取问题，不能由“修复守恒通过”证明它不存在。

落点：`table_compare/repair_context.py`、`business_repair.py`、`structural_repair.py`、`parser.py`、`facade.py` 和 `diff_builder.py`。增加独立、可复用的修复校验器；接入各修改入口时保留现有诊断。

验收重点：合计嵌入商品行、商品金额恰好等于合计、同值多行、跨页续行、单价与总价交换、金额清空、万元与元、真实金额修改。检查金额出现项去向与行列归属，不以总和相等作为通过条件。

## 4. 日期：标签、填写内容与识读状态分离

目标：空白模板不再构成填写值，部分填写及真实清空仍可检测。

在现有观测三态之外增加日期值完整度，例如 `PARTIAL / COMPLETE / INVALID / UNKNOWN`，保留 year/month/day 分量及各自来源。日期是否手写作为独立视觉属性，不参与“是否有值”的必要条件。

| 原侧 → 对比侧 | 目标行为 |
| --- | --- |
| `年 月 日` → `年 月 日` | 两侧字段区域确实可见且空白时，判一致 |
| 空白 → `2026年 月 日` | 确认部分填写，不能补全月日 |
| `2026年4月 日` → `2026年4月21日` | 确认填写日，变化框定位到 21，完整日期作为上下文 |
| 完整日期 → 图像中明确空白 | 确认清空 |
| 完整日期 → OCR 空字符串且被印章遮挡 | 待核验，不直接判删除 |
| 服务期限 → 同值服务期限 | 保留原字段身份，不因同页有签章就归为签订日期 |
| `2026年2月30日` | 保留可见原文并标记日期无效，不当空白，也不自动改正 |

对 `BUSINESS_CONTENT_REMOVED_OR_COVERED` 的确认分支单独审计：“被覆盖”不等于“已清空”，只有明确视觉证据支持的可见变化才能确认对应事实。标签、下划线、冒号及年月日单位属于模板，检测空白时排除这些笔画，但保留数字和无法识读的填写痕迹。

落点：`field_observation.py`、`signing_region/extractor.py`、`value_ocr.py`、`visual_recall.py`、`comparator.py`，并检查封面／表格日期路径是否复用相同规范化逻辑。

## 5. 跨页：先恢复逻辑内容，再做比较

目标：换页点变化不产生整段增删；换页同时修改内容仍能定位局部变化。

1. 复用页对齐，作为候选区域提示；保留跨更远页面检索能力，防止条款移动被单调页对齐排除。
2. 正文按编号、标题、句子连续性、段尾／段首关系建立逻辑片段链；表格按列语义、表头和页间内容建立续表关联。新标题、独立附件或冲突表头应阻止盲目拼接。
3. 先单侧恢复高置信逻辑内容。对仍不对称的切分，复用现有一对多／多对一匹配，记录每个片段的覆盖范围和未覆盖残余；匹配一个片段不能消耗整块其他内容。
4. 正文与表格表示互换时，使用“章节／表单身份 + 行标签／字段标签 + 主体 + 值”建立对应关系。先覆盖已知签署表单和问题样本，再扩展通用场景，避免同页无关表格被吞并。
5. 每个逻辑对象保持多源引用，局部差异映射回实际页和文字范围。重复页眉、表头的排除只影响比较视图，保留其源记录及排除原因。

落点：`page_alignment.py`、`clause_splitter.py`、`matching/structural_drift.py`、`table_compare/parser.py`、`signing_table_equivalence.py`，以及正文／表格差异证据生成路径。

验收重点：1→2 页、2→1 页、三页续表、中间插页、重复表头、同模板不同附件、正文↔表格、跨页同时改金额／否定词。逻辑一致场景不得产生确定增删；真实变化必须保留正确页码，未覆盖残余必须可见。

## 6. 条款：允许不匹配的全局选择与歧义处理

目标：改写和移动后仍找到对应条款；相似模板之间不强行配对。

1. 先记录实际启用配置、provider 可用性、召回来源和重排结果。不可用时明确记录退化状态，不能把未执行的语义分数当作低相似证据。
2. 复用编号、标题、词法和语义召回。除规则候选稀少外，对多个近似候选、低正文覆盖、结构漂移和未匹配条款也触发补充召回与重排。跨页移动时降低位置权重，但保持章节和文档类型证据。
3. 将配对分数转为经样本校准的配对收益，加入不匹配选择；移除或重新设计对配对数量的高额奖励。低质量多配对不能优于高质量配对加合理未匹配。不能把未经校准的模型分数解释为概率。
4. 判断歧义时同时检查两侧候选竞争、局部分差和全局替代方案。编号、标题完全相同但正文不同的重复附件需要单独消歧。差距不足时保留候选及原因，不直接确认修改。
5. 一对多／多对一关系纳入片段占用检查。优先为现有结构漂移处理增加覆盖约束和结果回检，复杂关系优化仅在剩余样本证明有必要时引入。
6. 配对后独立计算移动与修改。重新分页不等于条款移动；逻辑顺序或章节归属改变才进入移动判断。业务值变化由确定性 diff 保留，重排器只辅助身份判断。

落点：`matching/candidate_recall.py`、`candidate_scoring.py`、`candidate_policy.py`、`assignment.py`、`structural_drift.py`、`matcher.py`。先用影子运行对比 greedy、现有 optimal 与新策略，再决定默认值。

验收重点：原文移动、改写后移动、三个近似付款条款、同编号不同附件、候选数量相等但无真实对应、拆分／合并后残留修改、金额和“应／不得”变化。分别报告候选召回、匹配正确率和最终变化召回，避免只看最终差异数量。

## 7. 印章：将章文主体与盖章区域分别建模

目标：保留真实印章，避免归属错误被展示和后处理固化。

1. 分别保存 `seal_text_entity`（章文主体）、`signing_region_role`（所在签署区域角色）、`attributed_party`（综合关联结果）、候选及原因。名称对应通过合同已识别主体和别名证据建立，不按模糊名称强行合并公司。
2. 主体关联直接读取结构化字段和来源；移除从 `diff.title` 反推主体的决策依赖。标题只负责呈现结果。
3. 原绑定与视觉新候选一起复核：区域归属、章文名称、跨列关系、定位质量均作为证据。不能永远保留最早绑定，也不能让后来的邻近距离覆盖高质量证据。
4. 章文主体与区域角色冲突时分别展示可确定的事实，如“甲方签署区域存在印章；章文主体识读为某公司，归属待核验”。不把冲突压缩成一个高置信 party_role。
5. 骑缝章按跨页对象聚合，保留每页碎片；骑缝位置本身不支持甲乙方归属。同页两个独立章即使靠近或章文相同，也不能仅凭相似度合并。
6. OpenCV 检测与专用章文 OCR 在统一接口下提供候选。仅对章文不足、主体冲突等局部区域升级识别；是否新增模型由固定样本收益决定，不预设更换检测器。

落点：`signing_region/models.py`、`extractor.py`、`matcher.py`、`visual_recall.py`、`comparator.py`、`diff_builder.py`、`seal_ocr.py`。结构化结果变化时同步检查 API、报告和结果页。

## 9. 验证与发布约束

- **三组数据分开统计。** 正式 `contract-golden-v1` 继续阻断；已有候选 v2 用于问题开发；新增留出合同按整份合同隔离，同模板近重复尽量同组，避免边调参边验证。
- **按语义事件判定。** 使用稳定 case_id、原侧／对比侧事实、主体、页码和证据范围；历史 diff_id 只作追踪信息。一条真实变化拆成多个输出不能增加召回成绩。
- **每个修复同时有正反例。** 除前文样本外，增加重新分页、列顺序变化等内容不变变换，以及单个金额、否定词、主体交换等真实变化变换。验证结果而非复述实现。
- **指标不能相互替代。** 分别报告误确认数、关键变化漏报数、候选证据保留、主体错绑、重复事实数、待核验数及占比、定位错误、金额来源未覆盖数。确认与待核验分别统计召回，不以全部降级掩盖漏报。
- **两层回放。** 缓存 OCR 回放用于隔离算法变化；固定子集的在线 OCR 回放用于验证提取与渲染差异。模型、接口版本变化单独记录，不能混入算法收益。
- **正式门槛保持有效。** 按 README 的 `make golden-contract` 流程校验输入并执行正式阻断；失败必须定位原因。确需更新业务真相时，先提供原件证据和语义变更清单，按现有基线流程处理，不能自动修改 oracle 消除失败。
- **验证范围与改动相称。** 每阶段运行相关模块测试和必要回放；最终运行整体门禁。仅当新改动、失败或未解决疑点出现时扩大重复验证。本方案为文档，不运行业务测试。
- **性能预算用基线确定。** 记录每合同总耗时、匹配耗时、重排／局部识别次数、缓存命中和峰值资源；先测基线，再给可接受预算，暂不承诺无依据的延迟或准确率百分比。

首批实施交付物应包括：一份当前基线清单、金额修复覆盖诊断与回退机制、日期观测矩阵回归、五类问题的正反例目录，以及本轮回放对照报告。完成 P0 后再细化后续工作量。
