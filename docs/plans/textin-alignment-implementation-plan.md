# TextIn 接口、差异事件与页面对齐实施方案

日期：2026-09-09。状态：首批 PDF 纵向闭环已实施并验证；完整协议兼容尚未完成。详见 `textin-compatibility-matrix.md`。

## 目标与边界

将指定版本 TextIn 的接口行为、差异事件组织和页面交互作为产品兼容目标。保持已完成的误报修复。内部条款、表格、签章和视觉证据继续用于分析，对外统一通过差异事件输出；正常运行不依赖调用 TextIn，TextIn 用于基准采集和对照。

不以相同条数代替内容正确，不复制原图已经否定的识别错误。对于已验证分歧，记录原始证据、TextIn 项、本地项及裁定，不能把分歧藏入分组，也不能为了通过评测改写既有真值。

首个纵向样本使用 2eddbd7a-f029-4af1-9c97-c637d937e75f 的输入和现有 TextIn 保存响应，其 PDF 与 8eb0a225-3980-4021-8407-fa2cb2bb083d 相同。修复后 35 条是内部输出基线，不是目标展示条数。

## 当前工程事实

- 本地创建接口为 `/api/compare`，接收两份 multipart 文件以及有限选项；TextIn 创建接口采用 JSON 文档结构，存在文件数组、转换选项及预览访问流程，不能只改字段名。
- 后端同时有 `diffs`、`audit_items`、`diff_count`；前端 ResultPage 根据 audit_items 构造列表和统计，却用 diff_id 查找底层差异进行定位。存在多个计数/展示来源。
- ResultPage 当前双侧同步滚动基于整份文档比例；插页后相同比例不一定对应同一内容。
- 已保存 TextIn 响应：`diff_info.total=24`、`insert=13`、`delete=3`、`change=7`；diff_result 包含 1 条 MATCH。因此不能未经核实就强制 `total=insert+delete+change`。
- T19 将对比第 15–18 页的一段连续新增组织为一个事件；本地目前保留条款明细。T20/T21 为两个独立章。
- 尚未在本次规划中逐项观察真实 TextIn 结果页；页面布局、颜色、计数和操作细节需要先采集，不能把设计建议称为已确认的 TextIn 行为。

## 技术路线

现有比较引擎 → 原始差异与证据 → 统一事件构建器 → 持久化事件快照 → TextIn 兼容输出 / 本地事件接口 / 页面 / 导出报告。

一个事件包含：稳定 event_id、文档对身份、变化状态、对象类型、原侧片段数组、对比侧片段数组、页映射、子差异、原始差异引用、识读与变化证据状态、生成版本及审核投影。页码与坐标单位明确记录，不通过类型猜测。

同一个顶层事件在列表中出现一次，展开不增加顶层数量；多个跨页证据框不增加事件数量。不同物理印章、不同文件对、不同增删改方向、匹配内容隔开的变化不得仅因同页或标题相似而合并。

保留原始明细数、顶层事件数、变化事件数三个内部指标。兼容接口的 total 根据已冻结的 TextIn 口径序列化；页面标题必须说明展示的是哪一个指标，不擅自重解释 TextIn 字段。MATCH 的展示、筛选及统计按实际接口和页面分别确认。

## 阶段 0：冻结兼容契约与页面基准

工作：

1. 采集脱敏请求、成功响应、处理中响应、失败响应；记录端点版本、时间、文件哈希和选项，认证信息不进入样本。
2. 逐项登记文件结构、支持格式、单/多文档组合、默认值、merge_diff、忽略印章/水印/页眉页脚等选项、任务状态、错误码、分页和预览令牌行为。明确未支持项，不静默忽略。
3. 固定字段类型、缺省/空值、页索引起点、坐标参照、旋转页面、字符偏移、表格子结构、统计和 similarity 的含义。相似度算法若未公开，只承诺明确的返回契约，不承诺数值逐位相同。
4. 用实际结果页观察并记录：双文档布局、差异列表、选中和高亮、长事件展开、跨页跳转、筛选、缩放、联动、审核和导出。优先利用已有任务预览访问流程，不重新上传同一文件来代替查看。
5. 对公开文档与实际响应不一致的行为（例如 MATCH/total）做显式决策记录，选定兼容版本。

产物：兼容矩阵、请求响应夹具、页面截图/操作基准、差异计数定义、支持范围与分歧清单。

出口：每个 P0 行为都有输入、预期输出和可复现样本；不能用“与 TextIn 一样”代替字段规则。

## 阶段 1：统一差异事件与分组

主要落点：新增 `backend/app/services/diff_events/`，对接 pipeline 汇总、audit_summary、api_presenters 和数据存储。原始 DiffItem 不强行改造成外部协议。

工作：

- 根据页面对应关系、文本顺序、变化方向和中间匹配锚点组织连续新增/删除事件；多页事件保留每个片段及子差异。
- MODIFY 保留双侧精确内容；不同修改不因为文字相似或处于同一页而合并。
- 表格保留 cell/row/col/table 粒度和行列归属；印章按物理对象身份分开。
- 对 merge_diff 的开启/关闭分别定义事件行为，保留可追溯子差异。
- 事件 ID 在同一输入、选项和事件版本下确定生成；仅展开/折叠或排序不会改变 ID。
- 审核从原始明细映射至事件；成员审核冲突时不得自动视为整组通过，分裂/合并后保留历史及映射。

样本验收：T19 对应一个可展开的连续新增事件；T20/T21 为两个独立章；2.2.7 跨页内容只属于一个顶层变化。所有重要原始变化均能映射到事件或有带证据的抑制理由。

出口：事件结果可脱离前端单独检查，列表计数不依赖 UI 临时分组；本次日期、公司行、章文等已修复误报不重新出现。

## 阶段 2：TextIn 接口兼容层

主要落点：新增独立兼容 router、schema、serializer，复用现有任务应用服务和执行器；保留现有 `/api/compare` 接口。

工作：

- 先实现创建、状态/差异查询和预览访问的完整链路，再覆盖任务列表与删除等约定管理接口。
- 将文档数组、文件编码、转换选项映射到内部提交模型；格式转换和多文件组合按兼容矩阵实施。尚未实现时显式报不支持。
- 对齐 code/msg/data、result 数组、状态、对象类型、双侧 diff、子差异、字符框和统计。内部诊断字段保留在本地接口或独立扩展中，不随意污染兼容字段。
- 认证头如需同形兼容，使用本服务自己的凭据校验和权限；不复用 TextIn 的密钥作为本地身份。预览 URL 的令牌、权限和有效期按约定实现。
- 对齐页坐标、缩放与旋转变换；变换只在明确的适配边界执行。

出口：同一套契约测试可切换服务地址运行；支持范围内的请求和结果结构兼容，未支持参数没有假成功；相同事件快照反复查询结果稳定。

## 阶段 3：页面消费统一事件并对齐交互

主要落点：`ResultPage.tsx`、`PdfDocumentViewer.tsx`、`types.ts`、`lib/api.ts`、hooks 与相关测试。

工作：

- 页面使用统一事件接口驱动计数、列表、导航、高亮和审核；不再分别从 audit_items、diffs 重建不同口径。
- 按阶段 0 的真实页面基准调整布局、颜色、列表内容、筛选及展开方式。
- 一个事件可定位多个页面和框；左右显示各自真实页码，通过页面映射和内容锚点联动。新增页的另一侧展示相邻锚点/无对应内容，避免跳到错误同号页。
- 跨页、旋转页、缩放和虚拟滚动下，选中事件与高亮保持一致。
- 展开事件只展示子项；审核、导出及任务摘要引用同一事件 ID 和计数定义。
- 识读不确定与已证实变化分开呈现，保留查看证据入口。

出口：API 事件数、页面计数、导航数量和导出使用同一口径；对照实际 TextIn 样本验证定位与操作，而不是只做静态外观检查。

## 阶段 4：覆盖差距与质量对标

- 对保存的 TextIn 项建立一对一/一对多映射，列明对应、漏项、额外项、分组差别、定位差别和已确认的 TextIn 误报。
- 补齐当前二维码样图形等尚未独立表达的变化。先定义对象身份及兼容表示，不将其误当成业务表格或印章来追求条数相等。
- 在保留已修复反例的基础上，增加真实公司名、金额、日期、印章笔画变更，以及插页、跨页、旋转、同页多个章和表格合并拆分样本。
- 兼容性与准确性分别验收：接口结构完全一致不能替代原图正确；TextIn 项没有被本地复现也不能自动认定漏检。

出口：首个任务逐项可解释，没有无理由缺失的重要变化；不能只提交“条数相同”的报告。单样本完成后再扩大至文档格式、扫描质量及复杂布局样本集。

## 阶段 5：迁移、试运行与回退

- 事件输出独立版本化，保存原始结果与事件快照。新功能先在独立入口或开关下验证，支持切回现有展示。
- 历史任务不静默覆盖。可从已有结果重建事件的仅重建展示层；需要补充识别的重新执行并记录新 revision。
- 对既有审核结果做映射和冲突检查；无法确定归属的保留历史，不自动继承为新事件的确认结论。
- 先试运行首个任务及代表性回归集，满足门槛再扩大。记录耗时、结果大小、多页渲染性能与失败率，确保对齐没有导致不可接受退化。

出口：已有接口可用、历史审核不丢失、失败可诊断、展示可回退，新增结果的版本和生成参数可追踪。

## 测试与门禁

1. 协议测试：字段、状态、默认值、错误、空结果、多文档、预览、统计及坐标。
2. 事件测试：连续变化合并、独立章不合并、跨页不重复、重要内容守恒、ID 稳定、审核映射。
3. 原图正反例：误报消失与真实变化保留同时验证；不以待复核状态替代负例检查。
4. 页面测试：从列表、导航和高亮互相定位，筛选后计数一致，展开不重复计数，插页和旋转页面对齐。
5. 样本对标：分别报告接口兼容、分组、覆盖和定位差异，不用一个综合百分比掩盖问题。
6. 保持既有回归与 Golden。当前工作区已有 Golden 基线改动审批问题单独处理，不为兼容功能绕过审批或修改真值。

## 执行顺序与首个里程碑

按阶段 0 → 1 → 2 → 3 → 4 → 5 推进。接口协议夹具和页面观察可独立准备；事件定义未固定前不进行大规模页面重写。

首个里程碑：同一对兰溪/大唐合同通过兼容创建接口提交后，能够查询结构化结果并打开新结果页；T19 合为一个顶层事件、两个新增章分别展示、计数与定位一致，已定位误报不回归。完成这一纵向闭环后再扩展格式和样本，不继续以原始 35 条作为产品验收目标。

当前假设：建设本地引擎的 TextIn 兼容服务与页面，TextIn 不进入生产比对调用链；先验证 PDF 对比闭环，再按兼容矩阵补齐承诺范围。完全支持 TextIn 所有格式/组合属于后续完整兼容出口，首个里程碑不冒充全部完成。
