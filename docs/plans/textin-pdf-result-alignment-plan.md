# 单对 PDF 的 TextIn 结果对齐实施方案

日期：2026-09-09。状态：已实施并完成隔离验证；完整 Golden 门禁因已有基线审批未通过，未部署生产。本方案根据用户最新范围调整，作为后续实施顺序；不撤销此前误报修复和首批事件层实现。

实施结果见 [实施与验证报告](../reports/textin-pdf-v2-verification.md)。

后续统计口径优化见 [v3 实施与验证报告](../reports/textin-counting-v3-verification.md)，以其中的固定统计契约和验收结果为准。

## 目标与范围

在现有系统支持的单对 PDF 范围内，将差异覆盖、事件分组、差异输出和页面交互向 TextIn 对齐。认证头、预览令牌、多格式、多文件明确不在本轮范围，不作为本轮完成的阻塞条件。沿用本系统登录、上传和任务管理。

本轮不承诺 TextIn 全协议替代，不实施其应用密钥、令牌、格式转换或多文件组合。相似度算法、TextIn 专用列表/删除协议也不是结果对齐的前置任务。字符几何与表格结构仅针对已有可靠信息完善，缺失时明确表达，不填造数据。

用户可见的成功标准：该发现的真实变化得到表达；每项分组有依据；列表、导航、高亮、任务摘要、审核、导出使用同一个事件快照；与 TextIn 的剩余分歧逐项有证据和原因。

## 阶段一：建立可复核的差异真值与映射（P0）

工作：

1. 固定 PDF 哈希、TextIn 保存响应、当前引擎/事件版本、比较选项及对应文件。
2. 给 T01–T24 建立逐项记录：双侧页码、原图裁剪、TextIn 文本/类型、当前原始明细/事件、判断依据和结论。
3. 结论区分“已确认真实变化”“已确认识别误报”“证据不足”“分组/类型差别”“非变化 MATCH”。不得把证据不足直接归为误报；复核上一轮粗粒度对照表的表述。
4. 对四个图形项优先做相同位置的双侧核对，区分不存在、可见度变化、裁切、位置移动和图形内容变化。
5. 双向核对：检查每个 TextIn 项，也检查本地多出的项和页，避免只追踪 TextIn 已报告位置。

产物：`reference-items.json`、`adjudications.json`、双侧证据裁剪、逐项对照报告。每项都能追溯到输入哈希及证据坐标；历史 D 编号不作为当前结果的连接键。

验收：24 项均有明确分类和依据；未解决项单列；本地额外变化有记录。得到后续实现的测试样本，不先指定最终条数。

## 阶段二：补齐图形变化覆盖（P0）

工作：

1. 建立独立图形候选与对象匹配，使用页映射、区域位置、形状及配准后的图像证据。二维码无法解码不能解释为图形不存在。
2. 在可比较区域内判断新增、删除和修改；两侧都可见但浓淡不同的图形先验证内容是否变化。页面裁切或低对比导致不可观察时保留不确定性。
3. 保留对象类型、页号、区域、观察状态和判断理由。不要将一般图形套用成合同业务表格或印章。
4. 扩展内部类型/本地事件接口及消费方；TextIn 适配表示先形成契约决策。若其协议没有无歧义图形类型，明确兼容分歧，不能输出伪造的表格单元格。
5. 图形检测与现有章、签章区、页边细线检测共同去重，以物理对象重合为依据，避免一个对象多分支重复计数。

代码落点：文档视觉处理、页对应、事件模型/构建器、`api_textin.py` 适配边界及相关测试。以代码核查确定具体复用模块，不将全部检测放入序列化层。

验收：阶段一确认的真实图形变化均能定位和输出；相同内容不同清晰度不输出确定修改；真实替换、插入、删除仍被检出；未能观察的项不冒充确定结论。未知项没有被简单移到“待复核”来代替误报修复。

## 阶段三：明确并修正事件分组（P0）

规则：

| 对象/变化 | 分组规则 | 反例保护 |
|---|---|---|
| 连续文本新增/删除 | 按文档顺序和匹配内容边界分组，允许跨页 | 匹配正文、变化方向改变、独立位置不能被越过合并 |
| 同页多处修改 | 按实际变化位置与内容边界组织 | 不因同页、同标题或相似文字合并 |
| 水印 | 建议顶层按页、页内同一物理水印合并；用关联字段连接重复水印 | 跨页关系不等于同一展示事件；页内不同水印不误并 |
| 表格 | 使用真实单元格/行列身份，核查 TextIn 保存结构后确定展示层级 | 换行或 OCR 归属变化不视为单元格增删 |
| 印章与图形 | 按独立物理对象计数 | 两个章不能并成一个；不能并入长文本事件 |
| 单侧新增的 MODIFY | 只有移除新增片段后可还原另一侧内容，才转成新增展示片段 | 原始 MODIFY 与匹配尾部保留，不吞掉真正修改 |

工作：用阶段一样本验证水印按页建议并固定规则；建立 `textin-events-v2`，保存成员引用、规则版本及页映射。merge_diff=0/1 分别测试。严格记录历史拆组/合组映射。

验收：T19 一组且跨页明细不重复；T20/T21 两组；水印与 TextIn 的剩余分组差别有明确决定；每个原始差异都映射到事件或有可审查的拆分映射，不能无理由丢失。新事件数从规则计算，既不固定为 5，也不强制为 24。

## 阶段四：完善 PDF 范围内的输出与位置契约（P1）

工作：

- 输出差异片段及必要上下文，避免把未变化的完整尾部作为变化文字返回；对象、页号、双侧位置和原始明细引用可追溯。
- 统一页索引基准、坐标单位、显示旋转和缩放转换。以显示页 PDF point 为内部标准；若输出 TextIn 风格像素坐标，必须同时提供同一渲染尺度下的页面尺寸，不能混用。
- 利用已有 OCR 字符框生成可靠的逐字位置和字符偏移；只有区域框时保留区域定位及明确的精度状态，不用均分方框伪造字符位置。
- 仅对实际存在的表格行列/单元格关系输出结构；明确新增/删除/修改、跨页表格、合并单元格和缺失信息的表示。
- 固定 total、变化计数、MATCH 的处理，以及空结果、处理中、失败、无对应侧、无定位证据等响应。MATCH 不制造变化事件；与 TextIn 总数定义的差异公开记录。

验收：契约夹具覆盖上述状态和坐标；旋转页与插页的框均落在正确页面；每个变化片段在接口和页面能追溯到同一个事件；同一快照重复查询稳定。

## 阶段五：页面、摘要与导出统一（P1）

工作：

1. 用有效 TextIn 结果页采集真实列表、选中高亮、长事件展开、筛选、页间导航、缩放和联动行为。旧任务不可访问时，记录参考缺口；不能将本地设计称为已验证相同。
2. 调整事件列表文字、顺序、类型和页面高亮；单事件多框与子项定位均保持父事件选中，展开/折叠不改变顶层数量。
3. 加入新增图形与表格事件的筛选和证据查看入口；无对应侧明确提示，不按同页号或整份文档比例误跳。
4. 新任务详情、记录列表、导航、审核、JSON 和 PDF 导出统一读取事件摘要。内部 raw_diff_count 独立命名；历史记录没有快照时明确采用历史口径，不能把旧数伪装为事件数。
5. 审核拆分/合并存在歧义时保留原结论及冲突，不能静默整组继承“确认”。筛选后的导航只遍历当前列表。

验收：事件总数、列表数、导航数和导出数一致；类型筛选与待复核属性可交叉；同页多个章、跨页条款、旋转页、缩放、虚拟滚动和插页均通过操作验证。视觉同形未完成时明确限制该项验收，不影响已验证的数据结果。

## 阶段六：回归、显式迁移与启用（P1）

样本范围：首个合同 + 现有代表性回归集中的表格、旋转页、跨页和同页多章案例 + 本轮新增正反例。

必要正反例：

- 图形原样保留但改变清晰度；真实替换图形；新增/删除图形；页面裁切及淡色残影。
- 一个长新增段跨多页；中间插入相同正文后必须拆组；同页两个无关新增不误并。
- 同页两个章与同一个章的重复候选；真实章内笔画变化不能被抑制。
- 真实公司名、金额、日期变化保留；此前公司行、日期、章文和页边细线误报不回归。
- 表格换行重排与真实单元格变化；merge_diff 开关；合组后的审核冲突和过期 revision。

新增事件版本先用新任务验证。历史任务须显式重建展示快照或重新执行；若原图覆盖需要新识别，不仅重建旧事件。保留旧结果、版本和审核映射；切换展示后可返回旧快照。默认事件视图只在验收后启用，不先覆盖历史记录。

运行相关后端测试、前端测试、生产构建和适用的 Golden 门禁。本轮若改变检测器，必须重新验证检测结果，不能再只引用首批“原始 35 条不变”。现存 Golden 基线审批问题单列，不能改真值或绕过门禁来宣称通过。

记录处理耗时、输出大小和多页渲染表现，与本轮开始时的同样本测量比较；发现明显退化后定位原因再启用。单样本耗时不外推为系统性能承诺。

## 实施顺序与里程碑

按阶段一 → 二 → 三 → 四 → 五 → 六推进。有效预览的获取可提前进行；数据裁定和分组未固定前不做大规模视觉重写。

**M1：覆盖清楚。** 24 项双向对照完备，四个图形项逐项有结论；已确认真实变化完成检测和反例保护。

**M2：事件一致。** 分组规则固定，PDF 输出、列表、导航、摘要、审核及导出共用 v2 快照。

**M3：可启用。** 当前支持范围的回归、页面定位和迁移验证通过，未解决的 TextIn 分歧有证据；参考页缺失时不宣称视觉同形完成。

本轮最终交付：v2 实现、适用 PDF 契约夹具、逐项证据与映射、分组正反例、页面验证记录、回归报告和启用/回退说明。认证头、预览令牌、多格式、多文件不会进入未完成清单，也不被用来扩大本轮范围。
