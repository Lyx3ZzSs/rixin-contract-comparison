# 合同比对性能优化实施方案

日期：2026-09-15。状态：首批实施与组件验证完成；匹配裁剪和页面路由保持试验状态。实施证据见[验证报告](../reports/comparison-performance-optimization-verification-20260915.md)。

依据：[耗时根因分析](../reports/textin-speed-analysis-20260915.md)、[阶段指标](../../output/analysis/textin-speed-20260915/timing-evidence.json)、[页面对齐探针](../../output/analysis/textin-speed-20260915/alignment-probe.json)。

## 一、目标与执行顺序

先减少已经验证的重复计算，再缩小昂贵匹配的范围，最后改造文档识别路径。每阶段独立验证、独立启用；不把尚未测量的收益叠加成承诺。

参考长合同为同一对 55＋54 页 PDF，最近完整任务约 199–206 秒，最新阶段分布为解析 94.34 秒、页面对齐 46.89 秒、条款匹配 27.83 秒，其余约 37.11 秒。

| 顺序 | 工作 | 阶段目标（待验证） | 完成判据 |
|---|---|---|---|
| P0 | 固定基线、补足计时、建立可重放输入 | 能区分本地计算、外部调用与排队 | 输入/代码/配置可追溯，重复测量口径一致 |
| P1 | 页面相似度与特征复用 | 长合同页面对齐 ≤28 秒；完整任务争取 ≤190 秒 | 对齐及下游业务输出保持一致，缓存有界 |
| P2 | 减少候选评分和无歧义条款重排 | 长合同匹配 ≤12 秒；候选对减少 ≥50%，重排组减少 ≥60% | 已核真实变化无丢失、无新增已确认误报；完整任务争取 ≤170 秒 |
| P3 | 复用视觉渲染与检测结果 | 经计时确认的重复视觉工作减少 ≥30% | 同分辨率下输出不变，任务峰值内存增量受控 |
| P4 | 按页/区域组合原生解析与 OCR，优化扫描件慢路径 | 先验证最长 OCR 路径可否从约93秒降到45秒以内 | 先满足质量和真实调用验证，再制定90秒级完整任务目标 |

P1/P2 的完整任务目标针对相同服务条件的参考长合同；短合同不应有持续可复现的性能回退。P4 的 45 秒与完整任务 90 秒是探索目标，不是已证明的收益或验收承诺。TextIn 的21.49秒仍只能作为观察参考。

实施依赖：P0→P1→P2→P3→P4；P0 同时补采远端识别可用指标，尽早确定 P4 的外部服务约束。P1 独立有收益，不等待 P4 才交付。

## 二、P0：建立可比较的基线

### 0.1 固定输入、代码和配置

- 记录开始实施时实际代码内容哈希和选定配置；当前工作区有既有变更，不能只记录 HEAD 就声称固定了基线。
- 质量集使用现有 `contract-golden-v3`：15 对合同、30 个 PDF 哈希、255 条语义断言。额外加入本次 22＋22 页、55＋54 页两组参考合同的独立评估清单，避免它们不在当前 Golden 清单里而被遗漏。
- 55页重复任务只作为同一输入的多次测量，不当成多个独立样本。
- 参数调优集中在两组参考合同及明确指定的训练样例；其余合同作为保留验证集。固定金额/日期/主体变更、真实增删页、表格续页、手写签章和二维码变化的人工已核对照。
- 建立一次当前版本的质量基线。已有失败单列，不改写真值让性能版本通过；“没有新增失败”与“完整 Golden 通过”分别报告。发布沿用项目原有门禁。

### 0.2 拆出真正的成本

复用 `PerformanceRecorder`，在以下位置增加阶段总时间、工作次数和输入规模：

| 模块 | 新增或补充指标 |
|---|---|
| `pipeline_metrics.py` / `pipeline_stages.py` | 接受任务、排队、执行和完成时间；汇总细分时间 |
| `page_alignment.py` | 指纹构建、基础页/组合页相似度、锚点比较、DP、缓存命中/淘汰及峰值项数 |
| `matching/candidate_recall.py` | 召回来源分布、候选数、规则评分、embedding、rerank 等待、分配、回退原因 |
| `matching/providers.py` | 唯一文本数、模型/参数、实际请求批数、失败/重试、请求累计时间与整批等待时间 |
| OCR extractors | 编码、请求总时间、返回转换；服务端提供时才记录排队和推理时间，缺失记为 unavailable |
| `matrix_graphics.py` / signing visual | PDF渲染、候选检测、对象比较、图像复用、扫描页面数 |

禁止把嵌套阶段相加或把并发 HTTP 请求时长之和当成用户等待时间。没有底层可观测性时，不把 `http_request` 强行拆成网络和推理。

### 0.3 建立三种验证模式

1. **组件模式**：保存本次完整流程实际传入的文档、条款、页面对应关系；不重新识别，定位纯本地算法成本。上一轮探针使用的是准备前融合文档，P1补充准备后真实输入。
2. **确定性流水线模式**：固定 OCR 与外部模型响应，保持语义匹配、重排的逻辑配置，比较业务输出；报告缓存替代了真实外部耗时。
3. **实际调用模式**：保留正式OCR、embedding、rerank配置，测完整任务。记录服务状态和已知缓存情况；没有明确缓存旁路能力时标记未知，不能声称冷缓存。

**现有工具限制**：`replay_reviewed_tasks.py` 显式关闭 semantic/rerank，局部 OCR 默认也可能禁用。它可用于对应的离线算法检查，不能直接证明正式匹配路径正确或变快。实施时新增专用 `benchmark_compare_performance.py`，不悄悄改变现有回放脚本语义。

专用驱动需保存：输入/代码/配置哈希、全部运行模式、请求和缓存状态、阶段时长、CPU时间、峰值RSS、完整业务结果、质量报告。模型响应缓存以模型版本、完整参数和实际输入内容为键；新候选请求缺少响应时明确失败，不能伪造分数。真实新请求只在实际调用模式中执行。

### 0.4 测量安排

- P1组件基线与候选各至少3次，交替执行，报告中位数及范围；不在普通单元测试里断言机器相关秒数。
- P2/P4正式路径只对代表样本执行必要的真实调用，单任务基线/候选交替测5组；出现大波动先定位，不无条件扩大批次。
- 主要版本定稿后完成一次15合同完整质量验证及两组补充样本，再检查默认2个任务并发时的总吞吐、单任务等待和内存。
- 小样本报告中位数、最小/最大值，不包装成稳定P95/SLA。足量长期数据另行形成尾延迟指标。

## 三、P1：页面对齐计算复用

### 1.1 实施范围

主要修改 `page_alignment.py`；在 `pipeline_stages.py` 接入已有指标，并扩展 `test_page_alignment.py`。

1. 缓存归属于单次 `align()`，返回后释放，避免类实例跨任务残留和串数据。
2. 为基础页与相邻组合页分配带文档侧别的稳定键，预计算规范化文本、n-gram、布局集合；组合页特征复用。
3. `_similarity` 按有向左右键缓存；不能将A/B与B/A合并，不能只用页码作跨文档缓存键。
4. 锚点相似度也按有向文本对缓存；保持原计算顺序、公式、舍入和阈值。
5. 先采用50,000条相似度项作为可调上限，并记录实际RSS、命中率与淘汰。超过上限只重新计算，不省略状态；根据并发实测调整预算。避免缓存键重复持有巨大对象结构。
6. 第一阶段保留全部动态规划状态和拆并页尝试；缩小搜索带宽另列实验，不混入等价优化。

### 1.2 验收

- 复用现有相同页、插页、删页、合页、拆页、附件错配、低质量OCR、未确定删页测试。
- 补充跨任务同页码不同内容、左右顺序、缓存淘汰后输出、相同文档实例修改后重跑等真实错误边界。
- 当前参考样本与15合同：页面状态、对应页、分数、锚点一致；确定性完整链路中差异文本、证据、确认/待核状态和事件成员关系一致。
- 时间戳、诊断时长不参与业务输出等价；不可忽略差异项本身。事件ID只在不属于对外稳定契约且确有必要时按语义对应比较。
- 参考长合同页面对齐中位数目标≤28秒；若没有达到，按新计时定位锚点/全文比较，不靠删判断来达标。
- 缓存相关任务峰值RSS增量暂定≤64MiB，以两任务并发测量验证；预算不满足时调整容量后复测。

## 四、P2：缩小匹配工作量

这一阶段会影响匹配决策，与P1分开交付。主要涉及 `matching/candidate_recall.py`、`candidate_scoring.py`、`providers.py`、`matcher.py` 及相关配置。

### 2.1 先减少等价重复工作

- 预计算每条条款的规范化正文、编号、路径、业务字段及可复用特征。
- 合并同一批embedding中重复文本；原provider已有实例缓存和批调用，不重复实现已有能力。保持结果与输入索引正确映射。
- 相同模型输入重复重排时在单任务中复用；模型标识、版本、参数、候选顺序进入键，不把不同上下文错误合并。

### 2.2 再按歧义分配计算

- 建立唯一且高置信的对应候选：页面/结构关系明确、正文一致或充分相似、无金额日期主体冲突、无竞争条款争用时，才可跳过重排。
- 页面对齐稳定时优先同对应页、相邻页和同结构节；跨页条款、拆并页、附件及不确定页面保留较宽召回。
- 不把“同页”作为硬匹配证明，也不把“编号相同”作为跳过语义检查的唯一依据。
- 对分数差小、多个竞争候选、关键字段冲突或缺少可靠页对应的条款，继续rerank；top-k由有理由的候选决定，上限仍保留30。
- 无可靠结果或全局分配冲突时，扩回当前宽候选策略。回退尽量限定到受影响的匹配冲突组，保留完整回退能力。
- 初始只输出新策略判断和与原策略的差异；确认后才让新策略决定业务结果。阈值依据明确的评估集制定，不预先把“95分”等数值当作有效标准。

### 2.3 验收与目标

- 参考长合同候选对从37,903争取减至≤19,000；rerank组从367争取减至≤147；匹配中位数≤12秒。减少请求数本身不代表成功。
- 已核实真实金额/日期/公司/电话变化、增删页、签章变化不得丢失；已确认误报不得重新出现。
- 15合同及补充样本无新增语义失败、证据定位失败；策略引起的结果变化逐项给出输入证据与解释。
- 不通过质量验证则保持原策略，优先保留2.1中的等价优化。不得用更少差异总数判断匹配更好。
- 默认2任务并发检查服务限流、重试和CPU占用。已有embedding并发3、rerank并发8先保持，不能以盲目加并发代替减少工作。

## 五、P3：视觉处理复用

先用P0指标确认热点，再按收益实现，避免为全部流水线引入不必要的重构。

1. 在任务上下文中提供受限的页面渲染缓存，优先接入 `matrix_graphics.py` 和实际存在重复渲染的签章模块。
2. 缓存键包含文档内容标识、页码、缩放比例、色彩空间、旋转、裁剪和批注渲染选项；禁止把不同分辨率或灰度/彩色输入当成等价。
3. 相同图像和相同检测配置的候选结果可复用；检测版本进入键。共享图像只读或调用者复制，避免检测函数原地修改污染后续步骤。
4. 同任务只共享像素或只读结果，不跨线程共享可变PDF文档句柄。
5. 图像缓存初始字节预算64MiB/任务，按LRU淘汰，超预算重新渲染；与P1一起评估默认并发下的总内存。
6. 第一版不靠跳过页面、降分辨率来获取收益。如完整计时确认重复渲染不显著，停止扩大此阶段，转向P4。

验收：相同渲染参数下结果等价，二维码/图形增删与签章相关测试通过，重复工作时间减少目标≥30%；汇总阶段整体收益按实际记录，不把当前10.51秒全部算成可节省时间。

## 六、P4：识别路径改造

### 4.1 先确认服务能力和瓶颈

- 现有PP-Structure客户端提交整份PDF。先确认实际服务是否支持按页/区域输入、批大小、保留坐标、请求级与模型内部并发，以及可获取的排队/推理统计；不假设接口已支持未见过的参数。
- 原文PP-Structure约51秒、扫描件约93秒，二者已经并发。即使去掉原文请求，扫描件93秒仍可能决定总时间；原文优化的首要收益可能是算力/传输减少，不能直接算作51秒总时延收益。
- 评估扫描件重复OCR、表格/印章识别覆盖、服务资源竞争。若需要修改独立OCR服务，先明确对应仓库与部署边界，并在独立实验中验证。

### 4.2 分两步改路由

**P4a：页面级试验**

- 针对可靠电子文字页直接读取文字；纯扫描页走完整识别；混合或不确定页保留原路径。
- 可靠性不只看字符数，还检查字符框、编码异常、版式和图像区域。含图页不直接等于扫描页，文字层也不证明没有手写、印章或隐藏文字风险。
- 原生文字用于正文；表格结构、印章、签名、图片变化仍保留相应识别。页面子任务汇总后保留原PDF页码、坐标、阅读顺序和来源。
- 先记录路由决策，使用原路径输出做对照；再实际运行候选识别路径验证质量与服务调用收益。

**P4b：区域级与模型调用简化**

- 在页面级试验通过后，对混合页按正文、表格、签章等区域分配识别；无法确定归属时回退完整页。
- 评估PP-Structure返回的文字是否足以覆盖部分PP-OCRv5调用。只在已验证页面类型中减少第二路识别，保留双路模式处理不确定内容。
- 对必要扫描页验证批处理方案，禁止直接并发109个页面请求；从服务支持的有界批次开始，记录重试、排队、内存和结果完整性。
- 回退到完整页/完整文档时保存原因、耗时和来源映射；不静默把缺失页视为无变化。

### 4.3 验收

- 真实调用覆盖电子/扫描/混合文档、表格、跨页表格、签署区、旋转和低文字量页。
- 检查页数、来源、字符框、表格结构、签章证据与真实变化；不能只比较提取文本长度。
- 现有 `test_native_fast_path.py` 的保守全文件路径保留语义，新增页面路由入口和对应测试，不直接放宽原门槛。
- 用正式模型路径跑Golden和两组补充合同；离线OCR响应回放不能证明新解析路径准确。
- 确认最长OCR路径显著缩短后再重新计算完整任务目标。若扫描件服务仍约90秒，明确90秒级完整任务目标不可达，保留已验证P1/P2收益。

## 八、启用与退回

- P1/P3按单任务缓存设计，无持久化数据迁移；保留禁用配置以便比较和退回。
- P2/P4采用“关闭→仅记录候选策略→启用”的独立模式，默认不改变旧任务结果。仅新执行使用选定策略，任务保存策略版本。
- 开启顺序为两组参考任务、保留样本、默认并发验证，再进入常规使用。每次只更改一个阶段，才能归因。
- 出现已核真实变化漏报、证据缺失、完整任务失败或持续时延/内存恶化，退回该阶段配置并保留诊断。历史任务及人工审核结果不自动重算。
