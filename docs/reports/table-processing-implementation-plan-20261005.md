# 合同表格处理实施方案

日期：2026-10-05。状态更新于 2026-10-08：三个组件、独立 CPU 服务、后端接入及工程验证已实施；无线默认关闭，独立准确率验收和生产灰度尚未完成。结果见 [实施验证记录](table-structure-implementation-verification-20261008.md)。目标是提高实际合同差异的可用性，允许一部分难表保持待复核，不追求所有表格都自动成功。

## 一、确定的方案

采用原生优先、规则保留、分类分流的路线：

```text
现有 PP-DocLayoutV3 定位表格区域
    ↓
原生 PDF 提取 / 已有规则结果 → 检查通过则保留
    ↓ 未解决的表格区域
PP-LCNet 表格分类器
    ├─ 有线 → UNet + TableRecover
    └─ 无线 → SLANet_plus
    ↓
统一单元格与坐标适配 + 现有 PP-OCRv6 / PDF 字符证据归属
    ↓
结构与证据检查
    ├─ 可用 → 现有表格比较 → 对应文字的位置高亮
    └─ 不确定 → 原文和页面证据 + 待复核
```

分类器是分流依据，不能作为结构正确性的保证。无线表不使用“必须存在框线”的有线校验。模型输出只提供结构，文字和金额继续使用本项目已有证据，避免重复 OCR 和两份文字互相覆盖。

默认只调用一个结构分支。分类不确定或分支失败时，可进行一次受控替代分支尝试；两路均通过但结构明显冲突时保留待复核。不能直接比较两个模型的原始分数来确定正确结果。

## 二、接入位置和运行方式

保留 `ContractExtractionV3` 已有 `tables` 注入点，由 `TableResolver` 组织原生、规则和模型候选；继续由 `_publish` 负责正式结构发布和失败清理。无需更换整个 PDF 提取器。

生产采用独立的 CPU 表格结构服务，后端通过一个客户端调用。原因是后端目前没有 ONNX 模型依赖，已有 Layout/OCR 服务边界；独立服务可以避免每个后端进程复制模型，也便于单独回滚。开发验证先复用已经准备好的模型环境，不新增部署目标、不直接修改现有 Layout 服务。

拟新增职责如下，文件名为实施建议：

| 位置 | 职责 |
| --- | --- |
| `deployment/table_structure/` | 独立 CPU 服务、固定权重清单、健康检查、资源限制与启动配置 |
| `contract_v3/table_structure_client.py` | 发送裁图、校验响应、记录耗时，处理超时和不可用 |
| `contract_v3/table_model_adapter.py` | 原始输出转统一候选，处理 padding、坐标、逻辑跨度和框的对应关系 |
| `contract_v3/tables.py` | 原生/规则优先、模型分流、候选检查和回退 |
| `contract_v3/table_raster_evidence.py` | 有线表的实际边线证据，包括已知假边列和假内部分隔 |
| `table_compare/parser.py`、`diff_builder.py` | 将单元格关联到实际文字来源，生成紧贴变化文字的证据框 |
| `config_models.py`、`config.py`、`.env.example` | 模式、服务地址、无线分支开关、超时和并发限制 |

三个模型使用固定版本的底层组件，不能直接调用 MinerU 完整文档或 hybrid 初始化：当前 hybrid 构造有线/无线模型时会注入并加载自己的 OCR，而本项目已经有 OCR。UNet 使用结构接口；SLANet_plus 优先使用底层结构推理与解码，已有 OCR 的匹配由后端统一完成。

首版服务使用单进程、一次一个裁图推理、4 个 ONNX CPU 线程，不启用 GPU。模型在进程内复用，不按合同反复加载。后端按表区域调用而非整页重跑；响应后释放裁图及大中间数组。并发、超时及队列容量在实测后锁定，不用增加 Uvicorn workers 提高吞吐。

建议接口为 `POST /table-structure` 和 `GET /health`。请求携带裁图及输入尺寸/标识；响应包括分类标签与原始分数、模型/权重版本、原裁图坐标系中的单元格、行列及合并跨度、诊断和耗时。服务不返回作为正式原文使用的新 OCR 文本。完整线图等大诊断仅在调试模式保存。

## 三、实施阶段

| 阶段 | 工作和交付物 | 完成条件 |
| --- | --- | --- |
| P0：先修已证实的问题 | 处理表区域 OCR 证据关联；冻结实验输入、旧业务失败清单；明确候选数据与坐标契约 | 华北六项位置问题在真实差异链路得到验证，旧原文/字符来源保持；记录未涉及的历史问题 |
| P1：接入三个小模型 | 固定 PP-LCNet、UNet、SLANet_plus 权重与源码；做 CPU 服务及两个结构适配器；显式开启 UNet 倾斜修正 | 两个分支能独立运行；不加载第二套 OCR/VLM；响应经序列化后行列、框及来源保持一致 |
| P2：接入分流与必要检查 | 修改 `TableResolver`；保留原生/规则成功；接入分类、有限重试、有线边线检查和无线通用检查；建立文字来源索引 | 已知错表不会被当作已确认的错误增删继续比较；分类或服务失败能正常降级；真实空白列仍保留 |
| P3：验证并逐步启用 | 新旧结果对照、未知样本、15 份合同业务回放、资源测试；先影子模式，再有线，再无线 | 改动带来的收益和新增失败可逐项解释，达到下述首版目标，并能通过配置切回旧流程 |

P0 与 P1 可分别完成，P2 依赖两者；有线分支可以先进入灰度，不必等待无线分支全部完成。无线模型也必须在 P1/P3 实际测试，不能用有线 UNet 的结果替代验证。

### P0：金额证据关联

当前表格 HTML 挂在区域首个 block，例如“不含税价”；实际金额 OCR 位于同区域其它 block。`find_blocks` 和后续证据查找只拿到首个来源，找不到金额后回退为整个单元格框。本轮六项局部探针已证明实际文字位置存在，尚需验证正式差异链路。

短期改法：建立按 `page_no + table region/layout_block_id` 查询的文字证据索引；限定在对应格内寻找目标文字，重复金额用位置与原始 token 来源消歧。保存 `(block_id, text_index/token_id)`，不同 block 的字符下标不能混用。优先使用现成 OCR/字符框，找不到时保留格框并标明证据粒度，不能均分格宽伪造精确字符位置。

单元格候选的原始 token 归属也应保留到比较侧。首版兼容既有 `raw_html + table_cell_bboxes`，同时保存稳定 `cell_id` 与来源关联；无需立即重写全部比较模型。HTML 与框的对应关系由统一候选生成，不能从独立输出按序强行拼接。

### P1：模型适配和坐标

输入统一使用 RGB 原始表格裁图；明确页面 PDF、页面像素、裁图像素及模型转正空间。裁剪、padding、旋转和缩放都记录变换，最终候选回到原裁图/PDF 空间。转正后的逻辑推理使用转正几何，不能把逆旋转后的轴对齐包围框重新聚类成网格。

UNet 必须显式指定 `rotated_fix=True`。初版保持已经验证的策略：默认组件检查失败才 pad64，成功的默认候选不被覆盖。最终发布失败后的额外 padding 重试暂不启用：PO p8 证明这种重试可以修正金额局部，却仍将全宽标题拆成多个格子。

SLANet_plus 必须核查结构解码、框缩放、空占位框过滤与逻辑格的对应。源码中存在先过滤全零框、另行解码逻辑位置的流程，不能默认两个数组总能直接 zip。缺失或歧义的框明确记录，不借邻格补位置，不在后台自动运行额外 OCR。

PP-LCNet 的分数先用于记录和分流，不当作准确率。加入人工确认的有线、无线、弱框线和混合区域样本，检查分类混淆；低分阈值按开发集校准后锁定，不先凭空设定高分即可靠的规则。

### P2：只补有实际价值的检查

所有候选共用坐标合法、网格冲突、跨度、OCR/token 归属检查；有线候选额外核验实际边线。无线候选不能被有线框线规则拒绝。

本次重点修两个已知漏洞：假空白边列，以及全宽标题被模型拆出假内部分隔。按每一行段核验分隔线，避免把其它行的竖线延长为贯穿全表的列。真实空格不因没文字就删除；真实合并格不能按整表列模板强拆。对淡线、续表及开放边界设置不确定状态，避免用逐格四边全部清晰的规则误伤大量正常表。

不启动通用拓扑优化器、大规模规则重写或模型微调。先修可定位的接口、来源和分隔问题；只有剩余失败构成实际使用瓶颈，才另行立项。

模型超时、未安装、分类无法确定或结构检查失败时，只回退当前区域，保留原文和页面证据；结构服务不可用不应导致已完成文字提取的整份合同比较失败。未观察到一个格子不等于它被合同删除。

## 四、验证口径与首版目标

先给 58 张已见回归表补充本次关注的行列、金额、空格及合并关系参考；无需在开始接入前完成所有普通文字的逐字符标注。增加至少 60 张未参与调参的真实合同表作为首轮独立评估，尽量包含不少于 20 张无线表，并按合同/模板划分。数量不足时明确覆盖缺口，不用合成图替代真实无线准确率。

独立集的输入和评价规则在看结果前锁定。人工参考不能由待测模型自身生成；本轮助手核图可作开发依据，独立评估应有人工确认记录。原件与对比件的同模板表不能分别充当开发集和未知集。

以下为实施的建议目标，不是当前已达到的准确率或用户已确认的 SLA：

| 指标 | 首版判断方式 |
| --- | --- |
| 自动输出覆盖率 | 结构化输出表数 / 应处理表数；建议整体达到 85%，有线/无线分别列出，不以拒绝所有难表换好看的准确率 |
| 错误放行率 | 已结构化输出但人工判定存在实质结构错误的表数 / 已结构化输出表数；建议不超过 5%，单列涉及金额归属及合同差异的严重错误 |
| 金额处理 | 保持既有五个关键金额通过；华北六项位置修复进入真实链路；未知样本金额事实、行列归属和高亮分别统计，不合并成一个通过数 |
| 业务差异 | 与旧流程逐项比较新增/消失的事实，收益至少不被新增真实误报抵消；已知假列及错误标题不能直接生成已确认的虚假增删 |
| 分类 | 单列有线/无线混淆及误分流后恢复情况；最终以实际结构和业务结果评价，不把分类器高分计为成功 |
| 成本 | 在目标部署机器记录冷启动、单表 P50/P95、整份合同时间、峰值 RSS；首轮对照锁定资源预算，再决定是否增加并发 |

60 张只是首轮工程决策样本，允许继续接入和灰度，不支持宣称稳定的低百分比整体错误率。未达到目标时按失败种类调整、或缩小启用范围；不立即引入重 VLM。

当前 15 合同离线回放有 174 个历史 Golden 失败项，三条旧模式的总数相同，且包含其它模块及未收录的真实差异。本次不以“174 项全部清零”作为完成条件。应冻结旧失败事实清单，比较本次新增和解决的事实，区分旧问题、表格引入的新问题和正确的新发现；不会为了过关调整 Golden 阈值或删除断言。

相关测试重点是实际失败模式和接入边界：有线/无线分流，pad/旋转坐标回传，SLANet 空占位框，假边列/内部假分隔，真实空格，多次出现的相同金额，跨 block 证据关联，模型超时，以及失败状态经过 Document/JSON/比较后仍保留。现有结构、比较和 Golden 测试继续执行；不写只复述模型包装实现的测试。

离线业务回放继续复用冻结文字、关闭新外部读取，并披露未覆盖的补读分支。启用前再做少量新真实合同的实际提取/比较，以验证在线 OCR、Layout 与模型服务组合；不能把冻结回放称为完整线上验证。

## 五、启用和回滚

拟议配置采用三种模式：`legacy`（当前规则）、`shadow`（生成新诊断但继续使用旧结果）、`enabled`（使用通过检查的新候选）。有线和无线设置独立开关。具体配置名由实现时统一加入 Settings，避免散落硬编码。

启用顺序：本地组件验证 → 集成影子对照 → 有线分支灰度 → 无线分支灰度 → 扩大范围。灰度先覆盖内部明确选定的新任务；不重写历史任务结果。保存版本、分类、实际分支、重试原因、拒绝原因、耗时及差异证据。

发现新增严重错误差异、服务内存/延迟超预算或持续超时，关闭对应分支或切回 `legacy`。回滚仅影响后续任务；已完成结果保留生成时的版本和证据。不能因一次模型不可用丢失原始 OCR 文本。

## 六、执行顺序和范围

第一轮交付是“有线分支与金额定位可用”，第二轮交付是“无线分支及自动分流可用”。三模型运行、协议、校验、比较及回滚属于同一条连续工作，由当前执行者完成；无需为了划分组件创建多个并行任务。

首版不增加 VLM、RT-DETR、TableFormer、重复 OCR、公式模型或新的跨页拼表算法。既有跨页比较保持，通过实际回放发现的表格来源问题在本次处理；其它历史匹配、印章和条款问题留在原清单。

粗略工作量为 6–10 个工作日：P0 1–2 天、P1 2–3 天、P2 1–2 天、P3 2–3 天，P0/P1 可交错推进。这是基于现有实验环境的估计，不是交付承诺；无线输出契约和未知样本收集可能增加时间。执行时按阶段完成条件推进，不为凑时间跳过必要验证。
