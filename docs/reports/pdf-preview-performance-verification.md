# 合同 PDF 预览性能验证（2026-09-14）

状态：实现、独立审查和本地验证完成。默认启用准确页尺寸、共享调度、画布缓存及导航修复；下载继续使用默认流式策略。限速网络冷首屏降低 30% 的目标未达到。

## 范围

基于现有 PDF.js 预览新增准确页尺寸、双栏调度、Canvas LRU、跳转与缩放锚点、错误重试。没有修改差异识别、归组计数、证据筛选及报告生成逻辑；证据选择与高亮函数与本轮基线逐字一致。

实际验证任务为 `3b088e08-60ba-4525-8488-988a8e47b426`，原件 55 页、比对件 54 页；原始差异 79 条、展示事件 78 项、revision 64。记录固定快照是为了检测本轮是否修改了结果，不能把这些数量当作其他任务的正确性标准。

## 实现

- `GET /api/compare/{task_id}/preview-metadata` 复用任务权限，返回显示方向的 PDF 页尺寸。缓存按源文件大小和 mtime_ns 失效，不更新业务 revision。
- 双栏合计最多 2 个 Canvas 绘制任务，邻页最多 1 个；可见绘制未结束时邻页等待，可见任务到来可取消邻页。
- 默认预取窗口为可见页前后各 2 页。PDF 页面字典准备与 Canvas 队列分开，慢速取页不占绘制槽位。
- 直接借用已绘制 Canvas，闲置缓存预算 96 MiB；淘汰和失败时清空位图，退出结果视图时释放缓存与 PDF Worker。
- 使用 navigationId 和绘制代次阻止旧导航完成覆盖新导航。缩放保持页内锚点，元数据失败时从 PDF.js 读取真实页尺寸。
- 单页失败显示重试。认证头沿用现有行为，正常令牌轮换不重载文档。
- `VITE_PDF_TRANSPORT` 提供默认、`range64`、`range256` 构建选项，默认值的最终选择见实测结论。

## 测量方法

使用同一 Chrome 152.0.7977.54、1718×862 视口、DPR 1、默认缩放 80%；本地不限速及 20 Mbps/40 ms 两种网络条件。冷加载对照仅对测试标签禁用 HTTP 缓存，没有清理用户浏览器缓存或登录状态。生命周期压力验证允许 HTTP 缓存。CPU 未限速。本地静态测试代理未开启 HTTP 压缩，绝对耗时包含 JS 与 Worker 下载，不作为生产环境耗时保证。

两组均使用生产构建，经同一个本地代理访问实际 API。旧构建只增加 renderTask.promise 完成标记，不改变调度、下载、布局。冷首屏取两栏第一页实际绘制完成时间；跳转用 DOM 观察记录目标 Canvas 与 SVG 同时就绪，不包括测试工具轮询等待。首屏结束时的 Resource Timing 字节数不冒充首屏后 10 秒传输量。

原始记录位于 `output/analysis/pdf-preview-performance/`。`baseline-diagnostic.json`、`baseline-throttled.json`、`candidate-throttled.json` 是早期诊断记录。曾实测任务视图后台帧间隔为 1000–1017 ms；将任务视图在浏览器前台实际显示后恢复为约 16.7 ms。最终采样前检查帧率，限帧记录不计入验收。最终统计使用 `baseline.json`、`candidate.json`，不混用计时口径。

## 下载策略决定

默认保留现有流式下载。`VITE_PDF_TRANSPORT=range64` 可独立选择 64 KiB 按需模式，`default` 或不配置均回退到当前默认；不全局启用 `range256`。

最终网络采集采用短轮询，在观察画布的间隙读取并清空 CDP 事件，按真实导航时间截取前 10 秒。前几次采集曾因事件缓冲截断漏掉请求起点，对应的 `transports.json`、`transports-200.json` 中缺失传输量保持 null，不能用于字节数结论；最终字节数只使用 `transports-final.json`。

200 页样本的 200 个页面字典分布在 200 个不同的 64 KiB 区段，跨越约 82 MB。当前 PDF.js 在完成文档初始化前调用 `checkFirstPage` 和 `checkLastPage`；末页检查需要读取页树。结合约 404 次前 10 秒 PDF 请求，推断，页树对象分散是这个样本远程读取开销的重要原因。准确页尺寸与 Canvas 懒渲染无法消除 PDF.js 文档初始化所需的字节读取。

64 KiB 模式能减少真实合同的额外下载，但 200 页样本在导航开始后 10 秒窗口仅减少约 20.5%；真实合同在该窗口之后跳到远页的中位数由 279 ms 增至 728 ms，也不适合全局启用。256 KiB 在该大文件样本首屏中位数约 44.7 秒，明显慢于默认约 21 秒，直接排除，不再为已经失败的配置补做全量启用验收。

96 MiB 是闲置 Canvas 的位图预算，不是浏览器总内存限制。主线程 JS 堆、活动画布和渲染中画布分别记录；Worker 的堆字节数本轮没有统一测得，不能填 0 或宣称总内存不超过 96 MiB。

- 连续查看物理页 1–50，26→27→26 往返 10 轮，80%→160%→80% 缩放 10 轮，以及 5 次 SPA 任务切换均完成；另验证 54 页目标和合成 200 页目标能实际绘制。
- 26→1→26 两栏均复用同一个 Canvas 对象，绘制完成时间戳未变，证明返回时没有重新绘制。40%、80%、160% 的选中页脚差异框归一化坐标完全一致，并已查看原图截图。高亮代码与本轮前逐字一致。
- 旋转 90°/270°、非零 CropBox、混合页宽高均与实际 PDF.js viewport 一致。浏览器 DPR 切到 2 后，第 3 页 CSS 尺寸仍为 672×448，位图变为 1344×896。
- 延迟元数据响应时立即跳到物理第 26 页，实际滚动位置 17386 px、证据预期 17385.735 px，误差约 0.265 px；快速连续点击后仍停在最新目标。
- 独立审查复现了“目标先画完但前置页几何未齐，导航提前完成”的竞态；新增两项失败回归后修复。完成通知现在同时检查导航 ID、绘制代次及准确定位是否已应用；缩放前旧 Canvas 不能完成新导航。复审确认此项关闭。
- 压力序列采集 462 个帧间隔，中位数 16.7 ms、P95 17.5 ms、最大 17.8 ms；超过 50 ms 的帧间隔为 0，观察到的主线程 longtask 为 0。这是本次固定样本的观察值，不是所有设备的帧率保证。
- 闲置位图峰值 100,412,384 B（约 95.76 MiB），低于 96 MiB；活动位图峰值 19,873,652 B，其中渲染中峰值 5,001,344 B。双栏并发峰值 2、后台峰值 1。
- 退出后 running、queued、activeBytes、idleBytes、renderingBytes 均为 0，该测试入口的 PDF Worker 为 0，未处理错误为 0。另做 5 次同一视图进入/退出并 GC，监听器均为 771、DOM 节点在 47,638–47,645 间，无持续增长。CDP DOM/堆指标包含同进程其它浏览器上下文，不能直接当作该组件独占内存。
- 直连与本地同源代理的 Range 206、Content-Range、416 已验证；模拟忽略 Range 的 200 响应正常绘制两页。401/403 分别只发出两栏各一次失败 PDF 请求，显示错误，没有无鉴权重试循环。

原始证据：`functional.json`、`extra-validation.json`、`edge-cases.json`、`range-probes.json`、`page26-final.png`、`mixed-rotated.png`。额外验证脚本首次因跨 CLI 会话未重新安装指标监听器而超时；当时视图和 Worker 已清理。修正采集脚本后完整重跑通过，该超时不是页面残留。
