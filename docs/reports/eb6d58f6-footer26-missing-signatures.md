# 第 26 页页脚签字未标差异：根因分析

## 结论与页码

用户指出的“郭学童”对应页脚三处手写签注。**合同印刷页码 26 是 PDF 第 27 页，此页整组三处均漏报。** PDF 第 26 页（印刷页码 25）则只保留“郭”“☑梁”的两处 OCR 差异，右侧“童”漏报。具体姓名不能仅依据这些不一致的 OCR 读数确定，但原件没有、比对件新增手写墨迹的事实可由原图确认。

两种页码都已核对。这里是候选召回缺失：最终没有对应位置的差异证据，前端没有可绘制的高亮框。不是仅仅换了差异名称或被跨页合并后隐藏。

本问题在当前代码的新进程回放中也存在，**不能归结为上一轮发现的旧服务进程，重启不足以解决**。

## 一、证据在哪一层丢失

### 印刷第 26 页／PDF 第 27 页

1. **原图**：比对件页码下方中右侧有三处手写签注；原件对应位置为空。
2. **PP-OCRv5 全页识别**：最后一个识别项是印刷页码 `26`，没有这三处手写内容。
3. **PP-Structure**：检测到了 `vision_footnote`，原始框 `[608,1467,1013,1569]`，页面大小 `1190×1640`，文本只读为“童”。框覆盖整个签注组，不能把该单字当作三处签注的完整读数。
4. **Hybrid 融合**：将类型归一为 `footnote` 后，该候选没有任何对应的 OCR 子块。`_append_structure_only_regions` 的保留类型只有 `seal / figure / image / chart / formula / abandon`，另有有限签署字段例外；`footnote` 不在其中。因此候选被丢弃，融合文档中连区域证据也没有留下。
5. **页脚文字比较**：基于融合文档的 blocks 收集候选。输入没有签注块，无法输出本页差异，也无法凭其他页重复文字恢复本页的真实坐标。

### PDF 第 26 页／印刷第 25 页

PP-OCRv5 有“郭”“☑梁”，PP-Structure 除了“郭梁”还单独检测到了右侧“童”，原始框 `[956,1519,1014,1577]`。后者同样因没有 OCR 子块、类型不在保留范围而丢失。

最终 D003 在此页保留“郭”的证据，D005 保留“☑梁”的证据；右侧“童”无证据。因此该页属于部分漏标，不能说整页完全没有差异。

## 二、视觉兜底为何没有补上

`footer_annotation_visual.py` 的类和输出文案均按“左下角手写签注”设计，搜索范围写死为：

- 横向页面宽度 **2%—34%**；
- 纵向页面高度 **91.5%—99%**。

本页 PP-Structure 签注框位于横向约 **51%—85%**，完全在横向搜索范围之外。因此原图再清晰，这个兜底也不会检测该区域。

纵向还有第二个局限：签注组起点约为页面高度的 89.5%，部分上伸笔画位于 91.5% 边界上方。即使只扩大横向范围，框也可能只覆盖字的部分笔画。不能仅把 `roi_right` 改大便视为完整解决。

“全页签名召回”也未覆盖：`visual_recall.py:_signature_objects` 依赖“签字／签名”等局部标签或参会人标签，才能生成签名搜索区域。这些逐页签注没有标签，探针返回 0 个签名对象。

于是形成连续缺口：**文字 OCR 漏识别 → 版面检测独有候选被丢弃 → 页脚视觉区域不覆盖 → 签名检测缺少标签锚点 → 最终没有高亮证据。**

## 四、应怎样修复及验收

应以**签注区域是否新增**为第一判断，再独立判断文字读数是否可信。即使暂时读不准姓名，也应能输出“新增手写签注，文字待核实”及真实区域。

1. 保留没有 OCR 子块的版面页脚候选及其坐标、类型、来源；单字识别与大区域覆盖分开记录，避免把“童”扩展成整组姓名。
2. 结合印刷页码、页面正文底边、版面候选和邻页位置确定页脚区域，覆盖左、中、右侧及上伸笔画；避免把正文、页码和扫描边框纳入签注。
3. 对该区域进行原图配准及新增墨迹检测，补充无文字标签的页脚签注识别。其他页的签字只能提示搜索位置，不能代替本页证据。
4. 同一物理签注的 OCR 与视觉证据去重；跨页聚合时每个出现页面保留自己的证据。不要把“搜到某个名字”或“总数增加”作为验收标准。
5. 验收包括本页三处签注完整覆盖、PDF 26 右侧签注恢复、不误标印刷页码/正文/扫描边框，以及相同签注不重复输出。

上一轮验收主要覆盖 6 条已知纯误报及 4 处识读/归属纠正，没有建立逐页签注覆盖检查。这个遗漏说明减少误报和保持既有差异，并不能证明召回完整。
