# 当前项目表格路线选择

日期：2026-10-05。用户要求选择当前最优方案，允许合理的识别失败，不以百分之百准确为前提。

**选择：原生 PDF 保持当前原生提取；扫描有线表以 MinerU UNet + TableRecover 为优先结构候选，文字继续使用现有 PP-OCRv6。保留必要的结构检查与难表回退。** 这是当前样本、定位契约和资源约束下的工程选择，不是整体错误率结论。本轮选择未启用生产 provider。

## 完整表格处理的组成

以上 UNet 选择只针对有线表组件。若项目自动覆盖各种合同表格，建议增加 PP-LCNet 表格分类器进行有线/无线分流，并保留 SLANet_plus 作为无线表结构候选。PP-DocLayoutV3 定位表格区域，不能直接替代这种表格类型分流；当前生产 TableResolver 没有上述分类及无线模型分支。

推荐流程：原生表优先恢复；需要图像结构识别的表由 PP-LCNet 分类，有线送 UNet + TableRecover，无线送 SLANet_plus；两路均复用现有 PP-OCRv6 并接受结构及证据检查。分类不确定或识别失败时保留原文与待复核状态。单张已知有线表可跳过分类，但完整自动流程不能默认所有表都有边框。

这不是给每张表同时运行全部模型，也不需要重复加载 MinerU 的 OCR、公式、印章或 VLM 模型。分类器与无线分支尚未完成本项目独立验证；本轮的 UNet 成果不证明无线分支准确率。

## 选择依据

- 同一批五个关键金额，UNet 的文字、行列、跨度及图像/PDF位置全部通过；后续十个抽查金额也通过。抽查结果不能外推整体准确率。
- PP-StructureV3 已测 HTML 路线五个金额完整正确为 0/5；本轮绕过 HTML 的历史 detector 缓存消融改善到 3/5、九张难表有四张通过组件检查，但另外五张仍有重叠或漏 OCR 归属。没有证据说明它能补上 UNet 当前剩余难表，暂不增加为常驻模型。
- 已测 MinerU VLM 的内容与结构更好，但输出缺单元格坐标，同时不符合用户对轻量处理的偏好。暂不作为默认或必备回退。
- UNet 单独使用 CPU，权重约 8.3 MB；既有实测单表中位数约 0.36 秒，独立进程峰值约 1.48 GB。权重体积不代表总内存，本轮显式旋转后的延迟未另做性能基准。

## 最小落地范围

1. 显式传 `rotated_fix=True`，保留当前“组件失败才 pad64”的重试。58 张已见回归表的发布检查从 53 张通过变成 54 张，唯一变化是国网倾斜表从 15 列恢复为正确的 9 列；其他 57 张选中候选几何不变，旧八张行列参考与五个金额参考保持通过。
2. 修金额证据来源关联：按表格区域、页和单元格定位实际 OCR/token 来源，不只在 HTML 所挂的首个文字块里查找。华北六项局部位置探针全部达到现有阈值，IoU 从 0.169–0.296 改善到 0.811–1.000，不需要重新识字；尚未验证完整业务结果和确认状态。
3. 保留已经有效的假空白边列拦截。对已定位的内部假分隔及合并格问题，优先增加逐行段的原图线证据；不为每个特殊模板追加无证据的修补，也不把放宽检查作为提高通过率的方式。
4. 未通过检查的表保留原文与页面位置，输出待复核，避免作为已确认的结构化增删继续比较。局部识别失败可以接受；错误结构被确认为合同变更的影响更大。

最终发布失败后追加 pad64 的探索恢复了 PO p8 的 `35100` 两列跨度和两个 `16000` 四行跨度，也让现有发布检查通过。但原图的全宽标题仍被拆成多个格子，说明整表并未正确。本轮不把这个晚重试策略纳入所选默认方案，也不把其通过数当作准确率提升。

当前选择优先完成上述参数、证据关联及针对性检查，再验证合同差异。只有剩余难表的处理量足以影响实际使用，才增加第二个结构模型；到时优先做只针对失败裁图的 TableFormer 对照或 Paddle detector-only 补充验证。无需等待所有表都成功，也无需现在启动模型微调或全套大模型。
